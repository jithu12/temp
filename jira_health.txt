“So this Jira is mainly about standardizing our /health API based on the new SGCP Platform Health Standard document.

Currently in health.py, our /health endpoint returns a custom response format. It has separate dependencies and modules arrays, and the structure is specific to Dataviz.

According to the new platform documentation, all SGCP XaaS applications should follow one common health response format. So the purpose of this Jira is to migrate our existing implementation to that standard format.

When I checked the current code, I saw that the actual health calculation logic is already implemented properly. For example:

compute_status() calculates whether a dependency is UP, DEGRADED, or DOWN
it uses the sliding window logic based on Elasticsearch logger results
get_dependencies_statuses() fetches the logs from Elasticsearch
build_logger_search() builds the Elasticsearch queries
module health is currently computed using dependency aggregation

The Jira specifically mentions that these existing logics should remain unchanged. So we are not modifying the backend health computation logic.

The main work is on the response structure and schema.

Right now:

HealthResult contains status, version, comment, dependencies, and modules
DependencyHealthBlock and ModuleHealthBlock are used for serialization

Based on the platform document, we now need to:

remove the top-level dependencies response from the API output
keep dependency blocks only for internal computation
expose only module-level aggregation in the final response
add new fields like:
description
time
tags
rootcause
generate dynamic comments depending on module status
rename module names into the standard format like dataviz:application

So for implementation:

First I’ll update the dataclasses:

HealthResult
ModuleHealthBlock

Then I’ll modify:

compute_health_result()
check_health()
v1_from_results()

so that the returned JSON follows the new SGCP standard.

After that I’ll update the OpenAPI schema in api_v1.yaml and add the new Health and HealthModule schemas mentioned in the document.

Overall, the Jira is more about standardizing the API contract and response format, while keeping the existing health monitoring and Elasticsearch logic unchanged.”
